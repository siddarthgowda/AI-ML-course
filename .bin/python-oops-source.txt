PART 1: INTRODUCTION TO OOPS
------------------------------------------------------------

Q1. What is OOPs?
Ans: OOPs stands for Object-Oriented Programming.
It is a programming approach that organizes code using
classes and objects.

Q2. What are the four pillars of OOPs?
Ans:
1. Inheritance
2. Polymorphism
3. Encapsulation
4. Abstraction

Q3. What are the advantages of OOPs?
Ans:
1. Code reusability
2. Data organization
3. Easy maintenance
4. Flexibility
5. Scalability
6. Encapsulation

Q4. What is procedural programming?
Ans: Procedural programming organizes code using functions
and procedures.

Q5. Difference between procedural programming and OOPs?
Ans:
Procedural: Focuses on functions.
OOPs: Focuses on classes and objects.

Q6. Does Python support OOPs?
Ans: Yes. Python supports classes, objects, inheritance,
polymorphism, encapsulation and abstraction.

Q7. Is Python fully object-oriented?
Ans: Python is an object-oriented language, but it also
supports procedural and functional programming.

Q8. Give a real-world example of OOPs.
Ans:
Class: Car
Objects: BMW, Audi, Toyota
Attributes: Color, model, speed
Methods: Start, stop, accelerate.

PART 2: CLASS AND OBJECT
------------------------------------------------------------

Q9. What is a class?
Ans: A class is a blueprint or template used to create objects.

Q10. What is an object?
Ans: An object is an instance of a class.

Q11. Difference between class and object?
Ans:
Class:
- Blueprint.
- Defines attributes and methods.
- Created using class keyword.

Object:
- Instance of a class.
- Has individual data.
- Created by calling the class.

Q12. How do you create a class?

class Student:
    pass

Q13. How do you create an object?

class Student:
    pass

s1 = Student()

Q14. Can we create multiple objects from one class?
Ans: Yes.

s1 = Student()
s2 = Student()
s3 = Student()

Q15. Can multiple objects have different values?
Ans: Yes. Each object can have different instance variables.

Q16. What happens when an object is created?
Ans: Python creates an instance and calls __init__()
if it is defined.

Q17. Can we create a class without an object?
Ans: Yes.

Q18. Can we create an object without a user-defined class?
Ans: Yes. Built-in classes such as int, str and list
can create objects.

Q19. What is an instance?
Ans: An individual object created from a class.

Q20. What is an attribute?
Ans: A variable or property associated with an object or class.

PART 3: VARIABLES IN CLASSES
------------------------------------------------------------

Q21. What are the types of variables in classes?
Ans:
1. Instance variable
2. Class variable
3. Local variable

Global variables can also be accessed according to scope rules.

Q22. What is an instance variable?
Ans: A variable belonging to an individual object.
Usually defined using self.

class Student:
    def __init__(self, name):
        self.name = name

s1 = Student("Rahul")
s2 = Student("John")

print(s1.name)
print(s2.name)

Output:
Rahul
John

Q23. What is a class variable?
Ans: A variable defined inside a class but outside
instance methods. It is shared at class level.

class Student:
    school = "ABC"

print(Student.school)

Q24. Difference between instance and class variables?
Ans:
Instance variable:
- Belongs to individual object.
- Usually uses self.
- Each object can have a different value.

Class variable:
- Belongs to the class.
- Shared at class level.
- Access using class name or object.

Q25. What is a local variable?
Ans: A variable declared inside a function or method.

Q26. What is a global variable?
Ans: A variable declared outside functions and classes.

Q27. What is variable shadowing?
Ans: When a variable in an inner scope has the same name
as a variable in an outer scope.

Q28. Can we modify a class variable using an object?
Ans: Yes, but assigning through an object normally creates
an instance attribute instead of changing the class variable.

Q29. How do we modify a class variable?

class Student:
    school = "ABC"

Student.school = "XYZ"

PART 4: SELF, CLS AND SUPER()
------------------------------------------------------------

Q30. What is self?
Ans: self refers to the current object of the class.

Q31. Is self a keyword?
Ans: No. It is a naming convention.

Q32. Can we use another name instead of self?
Ans: Yes, but self is the standard convention.

Q33. What is cls?
Ans: cls refers to the current class.

Q34. Difference between self and cls?
Ans:
self = Current object.
cls = Current class.

Q35. What is super()?
Ans: super() is used to access the next class in MRO,
commonly used to call parent class functionality.

class Parent:
    def display(self):
        print("Parent")

class Child(Parent):
    def display(self):
        super().display()
        print("Child")

obj = Child()
obj.display()

Output:
Parent
Child

Q36. Can we use super() in multiple inheritance?
Ans: Yes. It follows MRO.

Q37. What happens if self is missing?
Ans: Calling the instance method normally through an object
usually causes TypeError if the method does not accept
the automatically passed object.

PART 6: CONSTRUCTOR AND DESTRUCTOR
------------------------------------------------------------

Q48. What is a constructor?
Ans: A special initialization mechanism used when an object
is created.

Q49. What is __init__()?
Ans: An initializer automatically called after object creation.

class Student:
    def __init__(self):
        print("Constructor called")

s1 = Student()

Q50. What are the types of constructors?
Ans:
1. Non-parameterized constructor.
2. Parameterized constructor.

Q51. What is a default constructor?
Ans: A constructor that does not require additional
user-defined arguments.

Q52. What is a parameterized constructor?
Ans: A constructor that accepts arguments to initialize
object attributes.

class Student:
    def __init__(self, name, age):
        self.name = name
        self.age = age

Ans: Not traditional constructor overloading.
We can simulate it using default arguments, *args,
or class methods.

Q54. Can we define multiple __init__ methods?
Ans: No. The last definition replaces earlier definitions.

Q55. What is a destructor?
Ans: A finalizer used for cleanup when an object is finalized.

Q56. What is __del__()?
Ans: A special finalizer method.

Q57. Difference between constructor and destructor?
Ans:
__init__() = Initializes an object.
__del__() = Performs finalization.

Q58. Difference between del and __del__()?
Ans:
del = Deletes a reference or attribute.
__del__() = Finalizer method.

Q59. Is __del__() guaranteed to execute?
Ans: No. Its execution timing is not guaranteed.
Context managers are preferred for resource cleanup.

---------------- INHERITANCE ----------------

Q61. What is inheritance?
Ans: One class acquires attributes and methods from another
class.

Q62. What are the five types of inheritance?
Ans:
1. Single
2. Multiple
3. Multilevel
4. Hierarchical
5. Hybrid

Q63. What is single inheritance?
Ans: One child class inherits from one parent class.

class Parent:
    def show(self):
        print("Parent")

class Child(Parent):
    pass

obj = Child()
obj.show()

Q64. What is multiple inheritance?
Ans: One child class inherits from multiple parent classes.

class Father:
    def show1(self):
        print("Father")

class Mother:
    def show2(self):
        print("Mother")

class Child(Father, Mother):
    pass

obj = Child()
obj.show1()
obj.show2()

Q65. What is multilevel inheritance?
Ans: Inheritance across multiple levels.

class A:
    pass

class B(A):
    pass

class C(B):
    pass

Q66. What is hierarchical inheritance?
Ans: Multiple child classes inherit from one parent.

class Parent:
    pass

class Child1(Parent):
    pass

class Child2(Parent):
    pass

Q67. What is hybrid inheritance?
Ans: Combination of two or more inheritance types.

Q68. Difference between single and multiple inheritance?
Ans:
Single = One parent.
Multiple = Multiple parents.

Q69. Difference between multilevel and hierarchical?
Ans:
Multilevel = Multiple inheritance levels.
Hierarchical = Multiple children share one parent.

Q70. What is method overriding?
Ans: Child class provides its own implementation of an
inherited method.

Q71. Why use method overriding?
Ans: To customize parent class behavior.

Q72. Can we override constructors?
Ans: Yes. A child class can define its own __init__().

Q73. Does the parent constructor execute automatically
if the child defines its own constructor?
Ans: No. Use super().__init__() when required.

Q74. What is the diamond problem?
Ans: A multiple inheritance situation where a class has
multiple inheritance paths to a common parent.

Q75. What is MRO?
Ans: Method Resolution Order determines the order in which
Python searches classes for methods and attributes.

Q76. How to check MRO?

print(ClassName.mro())
print(ClassName.__mro__)

Q77. Difference between super() and directly calling parent?
Ans: super() follows MRO and supports cooperative
multiple inheritance. Direct parent calls do not.

---------------- POLYMORPHISM ----------------

Q78. What is polymorphism?
Ans: One interface or method name can have different
behaviors depending on the object.

Q79. What are common forms of polymorphism?
Ans:
1. Method overriding
2. Operator overloading
3. Method overloading simulation
4. Duck typing

Q80. What is method overloading?
Ans: Same method name with different parameter lists.
Python does not directly support traditional overloading.

Q81. How can we simulate method overloading?
Ans: Using default arguments, *args and **kwargs.

Q82. Difference between overloading and overriding?
Ans:
Overloading = Same name with different parameters.
Overriding = Child redefines inherited method.

Q83. What is operator overloading?
Ans: Giving special behavior to operators for custom objects.

Q84. Give an example of operator overloading.

class Number:
    def __init__(self, value):
        self.value = value

    def __add__(self, other):
        return self.value + other.value

n1 = Number(10)
n2 = Number(20)

print(n1 + n2)

Output:
30

Q85. What is duck typing?
Ans: Python focuses on an object's behavior rather than
its actual class or type.

Q86. What is runtime polymorphism?
Ans: Method behavior is determined at runtime based on
the actual object.

Q87. What is compile-time polymorphism?
Ans: Polymorphism resolved during compilation, such as
traditional method overloading in Java.

Q88. What is encapsulation?
Ans: Combining data and methods inside a class and
controlling access to internal data.

Q89. Why use encapsulation?
Ans:
1. Protect internal data from accidental changes.
2. Control data modification.
3. Improve code organization.
4. Maintain data consistency.

Q90. What are access modifiers in Python?
Ans:
1. Public
2. Protected
3. Private

Q91. What is a public variable?
Ans: Normally accessible from inside and outside the class.

Q92. What is a protected variable?
Ans: Starts with a single underscore (_).
It is a convention for internal or subclass use.

Q93. What is a private variable?
Ans: Starts with double underscores (__).
Python applies name mangling.

Q94. Does Python support strict private access?
Ans: No. Python uses naming conventions and name mangling.

Q95. What is name mangling?
Ans: Double-underscore attributes are renamed internally
using the class name.

Example:
self.__salary

Becomes approximately:
self._Student__salary

Q96. What is a getter?
Ans: A method used to retrieve an attribute value.

Q97. What is a setter?
Ans: A method used to modify an attribute value.

Q98. What is @property?

Q99. Difference between public, protected and private?
Ans:
Public = name
Protected = _name
Private = __name

reason to change.

PART 22: SOLID PRINCIPLES STUDY NOTES
------------------------------------------------------------

Q305. WHAT IS SOLID
Ans:
SOLID is a set of five object-oriented design principles.

It helps create software that is:
    - Maintainable
    - Reusable
    - Flexible
    - Easy to test
    - Easy to extend

Q306. S - SINGLE RESPONSIBILITY PRINCIPLE
Ans:
A class should have one main responsibility
and one reason to change.

Bad design:
    One class handles database, email and reporting.

Better design:
    DatabaseManager
    EmailService
    ReportGenerator

Q307. O - OPEN/CLOSED PRINCIPLE
Ans:
Software entities should be:
    Open for extension.
    Closed for modification.

Meaning:
    Add new functionality without constantly
    changing existing tested code.

Example:
    Use inheritance or composition to add
    new payment methods.

Q308. L - LISKOV SUBSTITUTION PRINCIPLE
Ans:
A child class should be usable wherever its
parent class is expected without breaking
the program's expected behavior.

Meaning:
    Subclasses must correctly follow the
    behavior promised by their base class.

Q309. I - INTERFACE SEGREGATION PRINCIPLE
Ans:
A class should not be forced to implement
methods it does not need.

Meaning:
    Prefer smaller, focused interfaces
    instead of one large interface.

Python:
    Use small abstract base classes or
    protocols where appropriate.

Q310. D - DEPENDENCY INVERSION PRINCIPLE
Ans:
High-level modules should depend on abstractions,
not directly on low-level implementations.

Meaning:
    Depend on interfaces or abstractions
    rather than tightly coupling classes.

Python:
    Use abstract base classes, protocols,
    dependency injection and composition.

Q311. SOLID SUMMARY
Ans:
S:
    Single Responsibility.

O:
    Open/Closed.

L:
    Liskov Substitution.

I:
    Interface Segregation.

D:
    Dependency Inversion.

Q312. WHAT IS A METACLASS
Ans:
A metaclass is a class whose instances are classes.

Normal relationship:

    Class creates objects.

Metaclass relationship:

    Metaclass creates classes.

In Python, the default metaclass is:

    type

Q313. TYPE FUNCTION
Ans:
Check the type of an object:

    x = 10

    type(x)

Output:

    <class 'int'>

Create a class dynamically:

    MyClass = type(
        "MyClass",
        (),
        {"x": 10}
    )

    obj = MyClass()

    print(obj.x)

Output:

    10

Q314. CUSTOM METACLASS
Ans:
class MyMeta(type):
        def __new__(mcs, name, bases, namespace):
            print("Creating class:", name)

            return super().__new__(
                mcs,
                name,
                bases,
                namespace
            )

    class MyClass(metaclass=MyMeta):
        pass

When MyClass is created, the metaclass
customizes the class creation process.

Q315. METACLASS METHODS
Ans:
__new__():
        Creates the class object.

    __init__():
        Initializes the class object.

    __call__():
        Controls what happens when the class
        is called to create an instance.

Q316. METACLASS VS CLASS
Ans:
Class:
    Creates objects.

Metaclass:
    Creates classes.

Normal class:
    Defines object behavior.

Metaclass:
    Defines class creation behavior.

Use cases:
    Frameworks, class validation, registration,
    automatic class modification and ORMs.
